## 当前行为

Planner sometimes invents doc_id before calling knowledge.read_section, causing NOT_FOUND errors.

## 根因

Planner generates a read_section call without a preceding search to ground the doc_id.

## 备选方案

### 1. two-stage

Two-stage planning: search first, then plan read calls

- 取舍：Adds one planning step; reduces plan size

### 2. validation

Strict validation: reject any plan with an un-grounded doc_id

- 取舍：May reject valid plans; adds a validation step

## 选中的提案

Add a system prompt rule: 'Never guess doc_id; read it from a prior knowledge.search result. If you haven't seen the id, don't call read_section.'

- 指标：doc_id generation failure rate
- 基线：occasional NOT_FOUND
- 目标：0
- 方法：count doc_id generation failures in 100 runs

## 回放计划
