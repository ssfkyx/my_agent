# ADR-022：外发前的脱敏规则（Redactor）

- **状态**：已采纳（2026-10-30）
- **实现状态**：已落地（2026-10-30，TB-6 验收通过）
- **关联代码**：`agent/core/redact.py:Redactor`、`Redactor.redact_text`、`Redactor.redact_payload`、`agent/core/escalation.py:Escalator.escalate`、`agent/adapters/handle_to_master.py:HttpMaster`
- **关联 ADR**：ADR-021（升级必须先脱敏）、ADR-001（信封字段）
- **上游文档**：`docs/pre_architecture.md` §10（Handle_to_master：脱敏 + 传原始输入）

## 背景

升级会把用户输入与失败上下文发给场外的 SOTA API。必须"信息脱敏 + 传原始输入"：
既要保留足够的语义让远端能帮忙，又不能把密钥/身份/本机布局带出去。

纯数据流（结构化替换）比让模型"自己打码"可靠：模型会漏，正则不会。

## 决策

1. `Redactor` 是一组**顺序执行**的规则，全部是纯函数（输入 str → 输出 str）：
   - 私钥块 `-----BEGIN ... PRIVATE KEY-----` 到 `END` 之间整体替换；
   - `sk-`/`ghp_`/`AKIA` 等常见令牌前缀的连续串；
   - `key|token|password|secret = value` 形式的赋值（保留键名，屏蔽值）；
   - 邮箱地址；
   - 绝对路径（保留文件名与末级目录，替换前段为 `<path>`）；
   - 连续 32 位以上的十六进制串（哈希/ID）。
2. `redact_payload` 对 dict/list 递归应用；**只处理字符串**，数字与布尔原样保留（否则会破坏语义）。
3. 每条替换都带类型标记（如 `<email>`、`<secret>`、`<path>`），便于远端理解"这里被遮蔽了"，
   也便于事后核对脱敏是否过度。
4. 脱敏在 `Escalator` 内部、**发送之前**执行一次；`MasterPort` 实现不得再改动 payload（避免双重改写）。
5. 不提供"关闭脱敏"的开关：需要原文才能排查时，由人直接看本地 ledger，而不是把原文发出去。

## 理由

- 规则集而非模型：可测试、可审计、行为稳定（同一输入永远同一输出）。
- 保留键名与文件名：让远端仍能理解"这是读文件失败"，但不知道读的是谁家的哪个绝对路径。
- 标记化替换而不是删除：空串会让远端以为"用户什么都没说"，`<secret>` 明确表达"此处有敏感值"。

## 代价

- 规则会误伤（例如正文里恰好出现的 32 位 hex 会被替换）；这是可接受的保守偏差。
- 无法识别自然语言里的姓名/地址；如需更强保证，应改为"用户确认逐字段"的流程（未来切片）。

## 验证方式

- 断言：邮箱/`sk-` 令牌/`password=...`/绝对路径/私钥块/长 hex 六类样例全部被替换；
  普通中文与代码片段不被改动；嵌套 dict/list 递归生效；数字不变。
- 实跑：升级请求的 payload 中不含 `/home/cielo_1` 前缀。
