# 软件开发流程（关键步骤）

> 目标：用最少的步骤，把需求变成可验证、可回滚的交付。
> 适用：小到中型功能开发和缺陷修复；高风险项目在此基础上增加评审与灰度。

## 1. 需求澄清

- 明确目标、用户和使用场景。
- 写出可执行或可观察的验收标准。
- 明确范围与非目标，避免范围蔓延。
- 记录依赖、约束和主要风险。

产出：需求说明或 issue。

## 2. 方案设计

- 设计接口、数据流、存储和外部依赖。
- 明确错误处理、边界条件和安全要求。
- 对比备选方案，记录取舍理由（ADR）。

产出：设计说明或 ADR。

## 3. 任务拆分

- 拆成可独立验证的小任务。
- 每个任务写清输入、输出和完成标准。
- 标出阻塞项、先后顺序和回滚点。

产出：任务清单。

## 4. 实现

- 小步提交，保持单一职责。
- 先写失败测试或最小复现，再改代码。
- 处理错误路径、日志和配置。
- 不提交密钥、临时文件和无关改动。

产出：代码和单元测试。

## 5. 验证

- 运行单元测试、集成测试和必要的手工验收。
- 覆盖正常、边界和失败路径。
- 保存测试输出、关键日志和复现步骤。
- 验证未通过不得进入发布。

产出：测试结果和验证证据。

## 6. 评审

- 代码评审：正确性、可读性、边界、安全。
- 设计评审：接口、数据、依赖和回滚方案。
- 检查变更范围，拒绝无关改动。

产出：评审意见和修复记录。

## 7. 发布

- 确定版本号和变更记录。
- 写清发布步骤、灰度和回滚方案。
- 准备备份或数据迁移脚本。

产出：发布说明。

## 8. 观察与复盘

- 观察监控指标、告警和错误日志。
- 跟踪用户反馈，关闭问题闭环。
- 更新文档、ADR 和知识库。

产出：复盘记录。

## 最小完成标准（DoD）

- 验收标准全部满足。
- 测试通过，并有可核对的结果证据。
- 评审通过，问题已关闭。
- 发布和回滚步骤明确。
- 文档与知识库已更新。
